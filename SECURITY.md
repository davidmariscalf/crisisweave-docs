# Security Policy

CrisisWeave is designed for crisis-response evaluation and may eventually be used around sensitive operational information. Please report security issues responsibly.

## Reporting a vulnerability

Do not publish exploit details, credentials, private locations, personal data, or other sensitive evidence in a public issue.

Use GitHub private vulnerability reporting when it is available for the affected CrisisWeave repository. If it is not available, contact the repository owner through GitHub before public disclosure so a private reporting channel can be arranged.

Include the affected repository and revision, a minimal reproduction, expected impact, and any safe remediation ideas you have.

## High-priority classes

Privacy leaks, authorization bypasses, unsafe handling of stale or unverified crisis information, public exposure of operational-only worksite fields, unsafe offline caching, build-chain compromise, and failures that could make synthetic/evaluation assurances appear stronger than they are.

## Safe handling

Do not test against real people, emergency operations, or third-party systems without authorization. Prefer synthetic fixtures and local reproductions.
